# Персональные разборы резюме

23 небольших лендинга для GitHub Pages. Каждый разбор зашифрован AES-256-GCM отдельным случайным ключом. В репозитории и на Pages хранятся общий интерфейс и зашифрованные данные. Имена, тексты, PDF, ключи и общий список ссылок в открытом виде не публикуются.

Полная персональная ссылка содержит случайный адрес и ключ после `#key=`. Браузер загружает только один зашифрованный разбор и расшифровывает его локально. Фрагмент URL не передаётся HTTP-серверу. Текст вставляется через `textContent`; сторонних скриптов, шрифтов и аналитики нет. Индексирование запрещено метатегом; общего каталога людей нет.

Любой обладатель полной ссылки может прочесть и переслать свой разбор. Это доступ по секретной ссылке, без проверки личности. GitHub Pages остаётся публичным хостингом зашифрованных файлов. `noindex` сам по себе не защищает данные. При утечке ссылки потребуется новый ключ и адрес; уже прочитанный или сохранённый текст отозвать невозможно.

## Локальная работа

Нужен Node.js 22+. Зависимостей приложения нет.

```sh
cd /workspace/test
npm start
npm test
```

Сервер предназначен для локальной проверки; в продакшене работает GitHub Pages. Локальный сервер отдаёт только `site/`.

## Обновление содержимого

Открытые исходники разборов, PDF, ключи и список ссылок хранятся **за пределами checkout**, в приватной директории. Не добавляйте их в Git, GitHub Actions, Pages artifacts или логи CI.

Формат входного JSON: массив ровно из 23 объектов с полями `id` (номер), `name` и `sections` (шесть непустых строк в порядке критериев со слайда 12 презентации).

```sh
node scripts/build.mjs /absolute/private/reviews.json /absolute/private https://parunson.github.io/test/
VERIFY_PRIVATE=1 REVIEWS_INPUT=/absolute/private/reviews.json REVIEWS_KEYS=/absolute/private/keys.json npm test
```

Сборщик сохраняет прежние персональные адреса и ключи в приватном `keys.json`; для каждой сборки создаёт новые случайные IV. Каталог `site/` пересоздаётся. Общий список ссылок записывается только в приватные `links.json` и `links.md`. Сохраняйте `keys.json`, чтобы обновления не ломали уже отправленные ссылки.

Для замены скомпрометированной ссылки удалите соответствующую запись из приватного `keys.json`, пересоберите и опубликуйте сайт. Старый зашифрованный файл остаётся в истории Git; старую ссылку нельзя считать отозванной для человека, который уже сохранил этот файл.

## GitHub Pages

Публикуется **только содержимое `site/`**. Готовый сценарий `scripts/publish.mjs` создаёт отдельный коммит сайта в ветке `gh-pages`, сохраняя предыдущую историю этой ветки, и отправляет её через существующий origin. Исходники приложения остаются в основной ветке. Запускайте публикацию только после тестов.

```sh
node scripts/publish.mjs
```

В Settings → Pages выберите Deploy from a branch → `gh-pages` → `/ (root)` и сохраните. Для проекта Parunson/test ожидаемый базовый URL: `https://parunson.github.io/test/`. Публикацию и доступность этого URL нужно проверить отдельно. Доступ к Git не даёт права менять настройки Pages через API.

Каждому человеку отправляйте **только его полную ссылку**, включая `#key=…`. Общий файл со ссылками предназначен только для владельца проекта.
